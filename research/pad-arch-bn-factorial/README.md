# The 2x2 BN re-estimation on fitting/dev (C2, `PROTOCOL.md` §4): code, configuration and the pilot trial, registered before the complete runs and the test

`research/pad-arch-score-followup/PROTOCOL.md` §4 (registered with pull request #35) asks for a re-estimation of the
BatchNormalization moving statistics of the 48 saved checkpoints with frozen weights, crossing augmentation off/on with
upstream dropout off/on during the re-estimation only (cells E00, E10, E01, E11), and its order is: "Implement and test
on artificial arrays and the fitting/development partition. Freeze source, numerical tolerances, seeds, estimator,
estimands, thresholds, aggregation, group policy and exclusion rules before applying the new states to held-out data."
On the C5 card, on 24 November 2026, the coordinator wrote: "Per il 2×2 in C2 proceda come ha proposto, con una breve
prova su fitting/dev a pesi fissi e la pubblicazione del piano e del codice prima della valutazione sul test" (for the
2x2 in C2, proceed as proposed, with a short trial on fitting/dev with fixed weights and the publication of the plan and
of the code before the evaluation on the test); the C5 card description then says "Il 2×2 prosegue in C2".

**Status of this delivery.** This folder registers the code (`livenesslab/scripts/pad_arch_bn_factorial.py`), its
configuration, the note with the choices fixed before the trial and the analysis proposed for the registration
(`livenesslab/delivery/archbn2x2/NOTE.md`, the plan), the launch script, the synthetic suite and mutation check with
their logs, and the public record of the one trial that was run: `20261124-ARCHBN2X2-pilot-6c4d6d8`, scope `pilot`
(patience 4, fold 1, seed 42, LivenessNet and ResNet-18), **PASS at attempt 1**, 7,054.9 s of wall time and 45,024.4 s
of process CPU time, peak resident memory 5.43 GB. **No test frame was assembled or evaluated and no test score or
metric was read.** Every number of the trial is a fitting or development number, and the development frames were also
the early-stopping set of the checkpoints: every development number is in-sample (`NOTE.md` §4). The command that will
score the test is not part of this folder (below, "What this folder is not"). Nothing was run on Linux by the author.
